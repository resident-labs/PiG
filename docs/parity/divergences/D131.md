## D131 A stalled SSE stream that still sends keepalives ends after the semantic idle timeout (pi-mono #10761, #10762)

What: Pi's `httpIdleTimeoutMs` (default 300000) measures bytes after connection establishment. A gateway can lose the generation while continuing to send comment lines (`: keepalive`) or `ping` events, so that timer never expires. PiG also measures semantic progress on model SSE streams. A `data:` line of an event other than `ping` resets the semantic timers. After a reasoning or thinking event (Anthropic `thinking`, `thinking_delta`, `signature_delta` and `redacted_thinking`, OpenAI reasoning items and `response.reasoning*` events, OpenRouter, DeepSeek and Mistral `reasoning`, `reasoning_content`, `reasoning_text` and `reasoning_details`, Gemini `thought` parts), comment lines and ping events reset them too. Any later non-reasoning data event ends that exception. A reasoning configuration echo or a usage tally alone does not mark the stream as reasoning.

Timeouts: `StreamOptions.StallTimeoutMs` owns a request-start budget that includes CONNECT, TLS, response headers and time to the first event. Nil selects 180000 ms, a positive value overrides that budget, and zero or less disables only that budget. Headers do not restart it. An acquired non-SSE response keeps the request-start budget and close-on-cancel ownership; its bytes do not reset that budget or start the legacy SSE timer. The independent legacy `httpIdleTimeoutMs` semantic budget begins only after SSE response headers; its byte-level timeout begins only after connection establishment. A shorter legacy bound can end an established stream even when the new budget is larger or disabled. `httpIdleTimeoutMs: 0` disables the legacy budgets, not the new request-start budget. Both semantic timers restart on the progress rule above. Completion, read failure and Close stop the timers and detach or join the owned cancellation callback. A canceled custom Fetch body is closed even if it ignores request cancellation.

Failure: expiry cancels the request with typed cause `sseIdleError`. A custom Fetch returning only `ctx.Err()` cannot erase that cause. The provider reports the failure through its transport-error path; diagnostics record `provider_transport_failure` with error name `StreamStallError` and code `PIG_STREAM_STALL`, distinct from `SocketError` for an unexpected EOF. Error-status body readers preserve this typed expiry instead of reporting only the HTTP status. Completed HTTP errors retain their existing behavior, regardless of their message text. The existing assistant retry policy applies when enabled. A stream whose semantic progress arrives within both active budgets is not limited by its total duration.

Why: a stalled generation must end with an error, while a long silent reasoning turn behind keepalives is not a stall (owner sign-off 2026-10-10). The 180 s request-start default follows the owner's 2026-11-05 report of an 18 minute sol stall. A model that emits no reasoning event cannot use the keepalive exception.

Scope: `ai/sse_event_idle.go` owns the timers and progress tracker in one shared transport. The OpenAI Completions and Responses (including Azure and Codex SSE), Anthropic, Google (including Vertex), Mistral and pi-messages streaming boundaries carry the typed budget. Caller-supplied Fetch clients use the same watchdog. Non-stream image, classifier and OAuth requests retain their context and timeout behavior. Bedrock and the Codex WebSocket use other transports and are excluded. Dyna's sol route uses the covered OpenAI Responses SSE API.

Owner decision: 2026-10-10, lead ruling "fix it ... idle measured on semantic progress (events), default equal to httpIdleTimeoutMs"; owner sign-off 2026-10-10: reasoning and thinking events make keepalives count as progress. The new request-start budget does not replace that rule or move the legacy connection idle deadline into TLS setup.

Call-site markers: `ai/sse_event_idle.go`, `ai/openai.go`, `ai/openai_responses.go`, `ai/anthropic.go`, `ai/google.go`, `ai/mistral.go`.

Evidence: `TestStreamStallAfterEventsAbortsAndRetriesOnce`, `TestStreamStallBeforeTheFirstByteAborts`, `TestStreamWithSteadyEventsIsNeverAborted`, `TestStreamStallTimerIsStoppedWhenTheStreamCompletes` and `TestStreamStallBufferedReadCannotRearmATimerAfterClose`, plus `TestStreamStallGoogleBeforeHeadersProducesARetryableMessage` (`ai/stream_stall_test.go`); typed-option forwarding, every SSE API's actual stall, custom Fetch failure paths, independent pre-header timing, headers not extending the request-start budget, and disabled-budget legacy behavior (`ai/stream_stall_boundary_test.go`); `TestHTTPIdleTimeoutBeginsAfterTLS` (`ai/http_connect_timeout_test.go`); `TestOpenRouterImagesUpstream` (`ai/openrouter_images_upstream_test.go`); the comment/ping, reasoning/non-reasoning, line-ending and bounded-sniff-window regressions (`ai/sse_event_idle_test.go`); native/custom non-SSE 200/503 bodies, all eight APIs' stalled error bodies, completed HTTP error text, EOF cleanup, caller cancellation, and unmarked response identity (`ai/stream_stall_response_test.go`).

Parity allowance: Pi has no semantic SSE timeout. Hermetic provider tests exercise the intentionally different timeout and retry behavior instead of requiring equal Pi output for it.

Remove when: Pi bounds semantic SSE idleness across request establishment and body consumption.
