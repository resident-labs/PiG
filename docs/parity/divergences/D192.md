## D192 OpenAI and Codex Responses requests ask for reasoning.summary "detailed" by default

What: Pi sends `reasoning.summary: "auto"` with every reasoning effort (openai-responses.ts buildParams, openai-codex-responses.ts buildRequestBody) unless `reasoningSummary` is set. PiG sends `"detailed"` when `StreamOptions.ReasoningSummary` is empty and the provider is `openai` or `openai-codex`. Other Responses providers (xAI, GitHub Copilot, custom) keep `"auto"`. A request without a reasoning effort still sends no summary, and an explicit `ReasoningSummary` wins.

Why: on sol, `"auto"` returns bold headers only, so thinking shows no text. `"detailed"` returns the summary text. The sample does not measure the marginal token cost of a detailed summary.

Call-site markers: `ai/openai_responses.go` (`defaultReasoningSummary`).

Evidence: `TestResponsesRequestAsksForADetailedReasoningSummaryByDefault` (`ai/reasoning_summary_default_test.go`).

Parity allowance: the paired scenarios do not set a reasoning summary on an OpenAI provider.

Remove when: Pi's default summary text is the full summary on every model.
